entrain

clean-room Go · MIT licensed

A from-scratch reimplementation of the SBaGen workflow: reads .sbg today, authors a typed TOML format next. Renders WAV / FLAC / MP3 with true tone continuity, and ships beatscope to verify any renderer's output.

Quick start — the maintained fork

Same SBaGen, working audio on modern Linux, and a test suite that proves it.

# build
git clone https://github.com/desireco/sbagen && cd sbagen
make            # dev/sbagen-fixed — file output (WAV)
make alsa       # live playback on modern Linux — no /dev/dsp needed
make test       # 87-check regression suite

# play or render a session
dev/sbagen-fixed my-session.sbg
dev/sbagen-fixed -o out.wav my-session.sbg

The original 2011 release predates modern sound systems — upstream expects /dev/dsp (OSS). The fork's ALSA build plays live; the plain build writes files.

Questions

Is this the official SBaGen site?

No. The official home of SBaGen is uazu.net/sbagen — SBaGen is © Jim Peters and released under the GPL v2. This family page is maintained alongside the maintained fork; it is not affiliated with or endorsed by Jim Peters.

What changed in the maintained fork?

Only what had to change: defect fixes found while auditing the 1.4.5 code, a regression suite (golden hashes captured from the pristine upstream build, plus one test per fixed defect), a Makefile replacing the old build scripts, and the ALSA backend. The audio behavior of fixed builds matches upstream — that is what the golden hashes pin.

Which one should I use?

Want the classic tool working on modern Linux? The maintained fork. Prefer installers, Docker, or isochronic tones? SBaGen+. Building something new — modern formats, embeddable engine, MIT license? entrain.
